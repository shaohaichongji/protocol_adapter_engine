## 1. 结论与最短路线

公开 `CompileProtocolJson`、`CompleteRecordCodec`、`HostEndpoint`、`StreamFramer` **已有** ASCII 0.10/0.11 的执行能力：独立 RX/TX 模板由冻结 Plan 执行，Encode 调用期选 Message，Decode 唯一匹配，流式 STOP/精确 `bytes_consumed`/`Continue`/`Reset` 已可表达。不能因为当前 Lab 仍使用私有 adapter 就另造协议执行引擎。

当前不能只替换头文件和链接目标就无损迁移。0.10 的硬缺口是公开编译元数据未交付冻结后的 **ASCII 动作片段顺序、按动作字段引用与长度边界/记录上界**，以及 **唯一匹配后 Decode 失败的已知 Message 身份**；前者直接支撑当前字段输入容量、动作 `not referenced`、Decode-only 的描述和成功 TX 字段实际范围，后者支撑失败时已有的消息上下文。0.11 的公共 Framer/Host 运行状态足够处理流，但公开 capability 只有 stream 布尔值，未交付当前契约要求的静态 strategy/最大帧长 M；这一静态描述缺口可留到 stream 接线前补齐。成功 Decode 的 ASCII BYTES 目前确实是原输入切片，但公开头只明确借用寿命，未明确承诺“可由指针求实际偏移”；优先补清晰的公开契约/验证，若不能承诺则需只读实际字节范围，而不能反算 Raw 或重复 Decode。

推荐 **先补最小应用无关的 ASCII 冻结动作/失败身份事实 → Lab 0.10 完整记录的自有 DTO + public Codec/Host → 0.11 stream 的自有冻结后缀 + public Host/Framer**。共同的“编译描述→自有 DTO”映射可复用，但不先建设覆盖离线、显式 Host、流式三种生命周期的统一执行 adapter；它会让首片承担不必要的绑定/流状态/回调预算。0.10 仍须最终覆盖现有显式 Host Apply，不以只做离线路径宣称完整迁移。没有 Schema/TLV/Socket/UI 专用 PAE 接口需求。

## 3. 建议的最小调用链与切片顺序

1. **公共事实门**：在不扩 Schema/Core/协议执行语义的前提下，确认最小 ASCII action/field 长度事实、失败 matched Message 和 BYTES 原输入切片契约；0.11 的 strategy/M 可后置到 stream 片。现有 Frozen Plan 已有这些源事实，公共 API 只复制或借用只读视图，索引与 owner 寿命必须明确。若并行 PAE 报告证明某项事实已有可靠公开出口，以其现场证据消去对应提案，不为了阶段编号造接口。
2. **0.10 headless Lab DTO/执行**：在 `tools/protocol_lab_ui` 或局部 `tools/protocol_lab_ascii` 新建仅消费 `include/pae` 的 ASCII 自有描述/执行适配与测试。严格分类后 worker 调用一次 `CompileProtocolJson`，将 public `CompiledProtocol` 与作者/冻结动作事实保持到适配 owner；复制 `DocumentDescription` 后创建 public `CompleteRecordCodec`。Encode 从当前 TX Message 的被引用字段草稿生成 `EncodeValue::Bytes(FieldSelector,ByteView)`，以所选 Pipeline+Message 调用一次 `Encode`，只在 `status==OK` 时复制输出并用 TX segments/本次值长度校验实际范围；Decode 由所选 Pipeline 和完整 RX 帧调用一次 `Decode`，在 view+原帧仍存活时复制 message/字段、验证实际子区间，零字段照样成功。失败状态、可用身份、诊断帧与有效结果严格分离。旧 v06 Result/Review/Evidence 不承接 ASCII。
3. **0.10 UI 与显式 Host**：在 `compile_worker.*`、`schema_dispatch.*`、`document_session.*`、`document_tab.*`、`description_mapping.*`、`field_table_model.*` 的限定 ASCII 分支接自有 DTO，继续维护 `document/load/plan/selection/input/request` 修订和失败清理。显式 Apply 用同一 public compiled 候选准备 `HostBindingSpec`/public `HostEndpoint`；直接 Decode 用 candidate observer 复制，Encode 每次传 Message selector 并在 callback 借用期内复制，保留 binding/双流/替换取消门禁。私有旧分支及已验收 Binary H2 不同步重构。只有离线通过而 Host Apply 仍私有，不计完整 0.10 public 迁移完成。
4. **0.11 stream 后接**：先核实/补公共静态 stream 描述，再沿用 0.10 自有描述/Decode 结果物化，把 `StreamFramer` 或显式 `HostEndpoint` 每流 owner 接入。Lab 完整解析 chunk 后冻结 bytes/cursor；`Push` 的同步 noexcept callback 只复制本候选并 STOP（若走 Host，Host 内已对该候选 Decode 一次，Lab 不重复 Decode）；`bytes_consumed` 核界后推进 cursor，后缀只提交剩余切片，只有内部 pending 用空 `Continue`；过期/复制故障、无进展、Reset、转换确认取消、Reload 失败、Tab/Flow 隔离沿既有 Session/UI 契约。Encode 仍独立完整记录 TX，不经 RX Framer，也不自动补 CRLF。

共用 mapper 有实际价值：作者元数据、action 引用、输入转换、复制结果/诊断都可复用。但“先建一个同时替代 OfflineAdapter + HostObserverAdapter + stream 的共用执行 adapter”需要同时改编译 owner、Callback/Handle、流冻结状态和 UI 发布，首个可验证闭包反而变大；本报告不建议作为首片。对外构建接线在实施后才检查 `tools/protocol_lab_ui/CMakeLists.txt`、`tools/protocol_lab_ascii/CMakeLists.txt` 与根门禁：当前 UI 对私有 ASCII adapter/旧 Lab headless 链有依赖，根 `CMakeLists.txt:400-409` 仍要求 V10+UI 启用私有 adapter；不能为迁移笼统删除 V10/V11 CLI/Evidence 拒绝门。建议先 headless public-only 消费，再最窄 UI/Host 接线及旧分支隔离，最后按真实目标逐条检查 private include/链接是否从 ASCII 迁移片消失。
