# 03 配置、Schema 与诊断边界

回到[总入口](README.md)。先读 `lab/configs/synthetic_ascii_literal_only.pae.json` 与同目录的 `synthetic_ascii_literal_only.pae.yaml`：两份完整文件描述同一合成 ASCII 完整记录，`ascii_pipeline` 引用 `ping`，Decode 接受 `PING\r\n`，Encode 生成 `PONG\r\n`，字段为空。第一次改配置应复制完整文件到自己的工作目录；不要把下面的节选当成可编译配置。

| 同一含义 | JSON 节选 | YAML 节选 |
| --- | --- | --- |
| 协议 Schema | `"schema_version": "0.10"` | `schema_version: "0.10"` |
| 完整记录输入 | `"input_kind": "complete_record"` | `input_kind: complete_record` |
| 接收字面量 | `"text": "PING\r\n"` | `text: "PING\r\n"` |
| 空字段集 | `"fields": []` | `fields: []` |

`schema_version` 是 PAE 协议能力切片：0.9 为 Binary 有界流式，0.10 为 ASCII 完整记录，0.11 为 ASCII CRLF 有界流式；不是 YAML 语言版本，也不等于“高版本支持任意协议”。结构以包根 `schema/pae.schema.json` 为准，原始 JSON 字节和 Number Token 还受 `schema/strict_json_profile_v0.1.md` 约束。YAML 作者源遵循 YAML 1.2 单文档语法中的受限 `schema/pae_yaml_profile_v0.1.md`，不是任意 YAML：`"0.10"` 必须保持字符串；Anchor、Alias、显式 Tag、Merge、重复键、多文档和外部 include 不属于当前入口。需要保留数值外观的文本时加引号。

JSON 是 canonical 编译输入。YAML 先由可选前端转成严格 JSON，之后仍调用 `CompileProtocolJson`；它不增加新的协议执行语义。排错顺序是：

1. YAML 前端失败：看语法、Profile、重复键、资源限制与可用的原文行列；此时没有可继续编译的 JSON。
2. 严格 JSON / Compiler 失败：看 `stage`、`code`、`json_pointer`、`detail`；YAML 路线的 pointer 指向生成 JSON，来源映射可能精确、最近祖先或未提供，不把生成 JSON offset 当作原 YAML offset。
3. Codec/Framer/Host 运行失败：先看状态、输入字节和绑定。Framer 候选形成不是 Decode 成功，更不是业务回调交付成功。

公开示例和 Schema 是学习输入，不是客户协议。真实协议须按规格书逐条确认方向、长度、字节序、校验与异常规则；不要把客户资料、现场帧、密钥或内部路径放进此体验包。此包没有验证 Linux、真实设备、长期运行、稳定 ABI 或项目级对外分发许可。若某一能力只在 Schema 中出现，不能据此推断当前 Lab UI、SDK 配置或人工体验已覆盖。
