# PAE 宿主端点方向绑定与最小接入层契约

日期：2026-09-13。状态：用户先确认六项并授权落盘，随后授权推进PAE首片实现和Windows验证。
PAE首片已实施，Windows Debug/Release各32/32及三个配置门禁通过，见
[实施与验证报告](host-endpoint-binding-validation.md)。Lab接线、Stage、Commit、Push未获本轮授权。
下文保留约束和验收要求；具体C++名称和构建开关名称不冻结为公共API。

## 1. 已交付基线与六项决定

基线为`main@0636e178461078dd8b408e86b14a967afd4b6e5f`，已提交推送；PAE ASCII流式首片
为`716ff00`，Lab ASCII完整记录集成为`407af0d`。实施前重新核对HEAD、工作树与依赖。

现有[业务嵌入示例](../examples/business_embedding/README.md)由宿主查找固定业务ID、检查
direction_id并显式调用Core；[Binary流式示例](../examples/stream_framing/README.md)和
[ASCII流式示例](../examples/ascii_stream_framing/README.md)展示工作区隔离、消费游标和借用期。
这些不是通用端点注册层。本检查点复用这些已成立的约束，不重写Codec或Framer。

1. 新增默认关闭、内部试验性的宿主接入层；不建立完整Runtime，不冻结公共ABI。
2. 端点身份与Decode/Encode动作分离；注册时显式绑定Pipeline，不凭名称或rx/tx字符串猜动作。
3. Decode接收字节并输出统一字段键值结果；Encode接收字段值并输出完整字节，Binary/ASCII共用边界。
4. 不可变Plan可共享；每条逻辑接收流独立持有Framer/Core状态，首片串行调用且禁止重入。
5. 协议配置负责格式与规则；宿主注册负责端点、动作和Pipeline绑定，不引入地址、线程或设备配置。
6. Windows Debug/Release验证四种组合、错误绑定、隔离、Reset和失败零结果交付；
   不扩展UTF-8、网络、跨协议映射或自动转发。

## 2. 端点、动作与配置职责

这里的端点是宿主提供的逻辑身份，不是Socket、串口或物理收发方向。通信收到字节不天然意味着
Decode；具体动作由显式绑定及调用的输入类型决定。不将UI的Hex/ASCII表示选项当成协议模式。
Binary/Text及ASCII编码规则继续来自Plan，首片不新增协议Schema版本或绑定配置文件格式。

最小绑定语义为：端点身份、显式动作、Plan作用域、Pipeline身份；Encode调用还须提供属于该
Pipeline且支持Encode的Message身份。Decode由Core按该Pipeline匹配候选，不能由TX Message
选择器代替RX匹配。同一逻辑端点可分别具有Decode和Encode绑定；相同端点与动作的重复绑定拒绝，
不同动作不视为冲突。不提供按端点名称推断、缺省路由或失败后尝试另一Pipeline的行为。

注册必须在创建可用实例前完成校验：身份非空且无冲突、Plan有效、Pipeline存在、所请求动作有
可用Message、输入种类及Framer策略在当前编译能力内、资源预算可满足。Pipeline内允许存在仅支持
另一动作的Message，但不因此允许执行该Message不具备的动作。现有direction_id约束保留，
不能把该字符串直接当作Decode/Encode枚举，也不得绕过Compiler/Core的原有校验。

绑定表先验证并准备资源，再一次性发布；失败不留下部分可调用绑定。首片发布后不可变，
不做热重载、动态替换或在线解绑。变更配置/绑定须由宿主停止调用、销毁旧实例后重新建立；
旧Plan索引、字段引用及句柄不得跨实例使用。实例作用域身份须能拒绝误用，不能只依靠裸数组下标。

## 3. 调用与结果契约

| 动作 | 输入 | 成功输出 |
| --- | --- | --- |
| Decode完整记录 | 显式Decode绑定及一条完整字节记录 | Message身份、带身份和类型的字段键值结果 |
| Decode流片段 | 显式Decode绑定、逻辑流实例及字节chunk | 每个成功候选的同型字段结果，另报告Framer事实 |
| Encode | 显式Encode绑定、Message身份及类型化字段值 | 一条完整字节记录，不代表已发送或对端执行 |

统一输出是统一结果容器及字段身份/类型语义，不把Binary数值字段全部改成BYTES。
ASCII文本字段仍为BYTES；宿主负责字符显示、业务转换及变量字节编码。接入层不依赖QString，
不自动处理UTF-16/UTF-8，不补TX终止符、不经RX切帧规则重写TX输出。

错误绑定、动作不匹配、Message不属于Pipeline、输入类型错误在调用引擎前拒绝，不消费输入或
改变流。Core失败不交付部分有效字段或有效输出字节；零字段成功必须交付成功事实。
诊断材料与成功业务结果分离；不以候选交付数、API成功或Encode完成冒充协议成功/发送成功。

采用同步结果交付边界；字节和字段视图只在规定的当前调用/回调有效期内可用，字段引用还受同一
Plan存活期约束。宿主异步保存必须在借用期内复制。不得保存Framer候选借用指针到下一次Push。
回调异常不得穿过noexcept引擎边界；回调失败停止后续交付并保留实际消费事实，不宣称可安全重放。

## 4. 所有权、流状态与资源

Plan的拥有者必须晚于所有绑定和工作区销毁；不得双重拥有同一Plan。
每条逻辑接收流使用独立Core工作区，stream_chunk还使用独立Framer工作区；共享Plan不共享
可变流状态。Encode工作区与接收流隔离。首片无线程、锁调度器、任务队列或后台驱动。
同一实例所有操作串行；同实例回调重入须明确拒绝且不改变状态，不能仅依赖宿主自觉。

完整记录与流片段入口严格区分，不能把半包传给完整记录Decode来模拟Framer。
流提交保留既有bytes_consumed前缀语义、STOP、工作预算和内部pending事实；未消费后缀仍归宿主。
单次接入调用最多执行一次引擎Push，不自动循环耗尽输入。续提只提交准确后缀；空Push仅用于
已确认的内部待处理工作，不能将半包或丢弃等待状态强行完成。宿主示例驱动必须有调用次数及
无进展保护，不能自动重放整个chunk。

候选Decode失败不回扫已确认边界，不增加成功交付数；后续候选仍遵循Framer消费事实。
Reset仅清理目标逻辑流，不影响其他流/Encode绑定，不隐式刷新或交付半帧；宿主自行处理尚未
消费的输入。Reset开启新的流代次，旧代结果不得冒充新代结果。API/回调内部故障后先报告
准确消费状态，再要求显式Reset或重建，不隐藏为可恢复的零消费失败。

注册和工作区创建阶段按Plan及显式容量上限分配资源，检查乘加溢出和预算失败；不引入无界
注册增长、缓存、结果历史或队列。接入层不得削弱原Framer有界/预分配承诺。
报告分别说明引擎、接入层和宿主复制的分配范围，不把宿主回调分配误称为引擎热路径零分配。

## 5. 实施边界与顺序

能力默认OFF，缺依赖在配置阶段明确拒绝，不暗中开启V10/V11或Lab。共享布局宏传播一致，
构建支持的Schema/策略接受域须在实施报告列明，不把四种组合宣称为所有历史Schema兼容。
新层依赖现有Compiler/Plan/Core/Framer，Core和Framer不得反向依赖宿主层、Qt或Lab。

1. 契约已冻结并获得后续PAE代码实施授权；Lab仍在后续独立停点。
2. PAE先完成绑定校验、生命周期、显式调用分派、流隔离和公开合成宿主示例及回归。
3. 总控定向复核接口、错误零交付、消费语义、资源和构建门禁，完成Windows验证报告。
4. PAE接口稳定后另行确定并授权Lab接线；仅观察绑定和执行状态，不接管业务/通信管理。
5. 不同时派发两侧修改同一未稳定接口或CMake/公共配置；通过已完成证据交接依赖。
   Stage、Commit、合并、Push按各自明确授权执行。

UTF-8、真实UDP/TCP/串口、端点连接生命周期、线程/重试/定时器、跨协议字段映射、自动转发、
Lab历史/导出、CLI/Evidence扩展、安装导出及稳定公共ABI全部排除。既有历史UDP实验不因本文
变成新接入层的通信验收。发现必须改变Schema或原引擎协议语义时停下评估，不顺带实施。

## 6. Windows Debug/Release验收矩阵与停点

以下为验收要求，实际执行范围及结果以验证报告为准；使用公开合成配置和独立手算期望值，
不使用客户协议或生产端点。

1. Binary Decode/Encode、ASCII Decode/Encode四种组合；验证正确字段身份、类型、值和完整字节。
   覆盖独立RX/TX规则及Decode-only/Encode-only，不能只用自身Encode输出自证Decode。
2. 缺失/重复端点动作绑定、未知Pipeline、不可用动作、不属于Pipeline的Message、错误输入类型、
   跨Plan/实例句柄误用、资源准备失败：拒绝且不发布部分绑定、不交付结果、不污染已有状态。
3. 同端点两种动作及两条独立逻辑接收流共享Plan；交错半包、Reset一流、Encode执行均不串扰。
4. Binary既有有界策略与ASCII CRLF流接入：分片、粘包、跨块边界、STOP后缀续提、预算残留、
   内部pending空续提及无进展保护。候选失败后合法候选可继续，超长恢复保持既有引擎语义。
5. Core失败零业务结果、零字段成功、回调失败实际消费、借用期内复制后宿主保留数据、
   同实例重入拒绝、流代次及销毁顺序；异常不穿越引擎边界。
6. 默认关闭、缺依赖拒绝、启用组合构建、无Qt宿主示例、共享宏一致及受影响旧能力回归。
   报告写明工具链、完整构建命令、测试集合、结果与未重跑集合，不累加不同批次伪称最终全量。

人工窗口验收是后续独立检查点。不得升级为Linux、性能、网络、Golden、硬件、部署或现场通过。
