# PAE / Lab 职责与独立交付边界

状态：2026-09-14 用户确认方向并授权分片执行。本文是当前工程整理依据，不表示下述 SDK 和交付能力已经实现或验证。

## 1. 已确认的产品边界

- PAE 是纯净、应用层无关的协议基础设施，包含 Compiler、冻结 Plan、Core、Framer、Host；第一版作为完整产品交付，暂不拆成多个独立产品。
- PAE 不依赖 Lab 或 Qt，也不包含 UI 专用语义；不默认管理 Socket、串口、设备线程、重试、业务路由。
- Lab 是 PAE 的上层消费者：使用公开接口，加上自身应用适配和 Qt 界面。Lab 不成为第二套协议执行引擎。
- 通用协议元数据、布局事实和诊断属于 PAE，可选查询；界面布局、展示文本组织、交互、Tab/Flow 展示缓存属于 Lab。不能仅改 UI 名称便宣称完成解耦。
- 先采用 C++17 公开 API，明确所有权、借用期限、对象销毁和工具链兼容范围；暂不提供 C ABI，不承诺跨编译器 C++ ABI。
- 允许有边界地调整内部接口并同步迁移 Lab、示例、测试；不改变已确认的协议/Schema 执行语义、不删减已有功能。发现外部使用方依赖受影响接口时先报告。

## 2. 独立交付目标

先闭合 Windows x64 三种交付：可独立构建的源码包、静态库 SDK、动态库 SDK。消费者不需要克隆整个开发仓库。

- 源码包包含公开头文件、必要实现、构建入口、所需依赖及许可证、Schema、最小示例和使用说明；不依赖开发仓库之外的私人路径或构建下载。
- 静态/动态 SDK 包含必要头文件、库、CMake 消费入口、最小示例、依赖与兼容说明。静态包必须闭合链接依赖，动态包必须闭合运行时与导出接口依赖。
- PAE 包采用白名单，不包含 Lab、Qt、开发测试、spikes、历史构建产物、Git 元数据或私有协议资料。
- 同一公开 API 支持源码、静态和动态消费；内部模块拆分不强迫用户逐项理解和链接。
- 记录架构、编译器/工具集、运行库、Debug/Release 等兼容条件；不把一个 Windows DLL 声称为任意工具链可用。
- Linux 是明确目标，等待用户补充真实环境后独立验证，当前不宣称 Linux 成品可用。
- 本轮不涉及正式上传或发布；PAE 许可证及发布位置在必要时由用户决定。保留第三方许可材料，不修改本机 Qt 5.11 或随仓 Qt。

## 3. 文档组织

`docs/README.md` 保留总入口，主要分为：

| 目录 | 用途 |
| --- | --- |
| guides/ | 面向开发者的能力说明、构建、配置、嵌入、Lab 使用和排错 |
| engineering/ | 当前有效契约、设计决策、维护与验证依据，供迭代查阅 |
| archive/ | 已被替代但仍有追溯价值的历史设计、计划和记录 |

按用途与效力分类，不按作者或文档年龄分类。有效契约不能仅因时间早而归档；验证记录不能替代契约；历史证据不等于当前验证结果。
文档迁移须保留既有内容和未提交变更，修正相对链接与入口。重复/无价值文件列为删除候选，不自动删除。
用户已删除外层“Lab验证”和“工程整理归档”，不要重建；指向其内容的历史路径应标记不可用，不宣称归档仍存在。

## 4. 执行顺序与责任

1. 总控落盘本文，统一授权与职责边界。
2. 《PAE工程整理》盘点并整理 docs 三分区、总入口和迁移映射；只做文档，不更改执行代码或构建行为。
3. 《子任务推进》只读梳理公开接口/依赖/静动态库边界，《Lab应用推进》只读梳理 Lab 对 PAE 内部接口的消费及最小迁移范围；向总控交付分片建议。
4. 总控审查后定向派发代码/构建切片，公共接口与根 CMake 串行协调；先保持已有行为，再验证公开接口消费。
5. 验证仓库外 Windows x64 源码、静态、动态最小宿主消费，再验证 Lab 消费公开接口。
6. 最后整理失效目录和产物；不可恢复删除另列目标请用户确认。

## 5. 验证与停止边界

- 文档阶段检查迁移完整性、链接、索引和既有变更保留，不无意义重复构建或人工截图。
- 接口/构建阶段做受影响测试与 Windows Debug/Release 验证；交付阶段必须验证仓库外消费，不能用仓库内链接成功替代。
- 实现、自动测试、人工试用、Linux、真实项目和生产证据分别说明。
- 超出职责、新功能、Schema 语义变化、外部兼容破坏、许可证、环境变更、不可恢复删除或正式发布，先向用户列出依据、影响和推荐方案。
- 本轮未授权 Stage、Commit、Push。子任务达到派发停点后主动向总控反馈一次，停止写入。
