## 2. 接口差异与最小补充

现有Lab直接捕获Framer候选、复制原帧并STOP，再执行Inspect；宿主Session只向业务Sink
交付成功结果，失败候选继续，Decode输出不含完整原帧。不得直接替换而丢失失败诊断或单步边界。

新增的是内部、可选、同步诊断接口，不是业务失败结果输出或持久化事件系统。具体类型名称
在实施时确定；不扩展Core/Framer协议语义，不冻结公共ABI。

- 每个已进入Core的Decode候选只执行一次Core；观察包含原帧、Core状态、有效Message身份、
  可用失败定位及流代次。失败时不得将部分字段标记为有效业务结果。
- 完整记录Decode同样可观察一次执行；API早拒绝未执行Core时不伪造候选。
  Framer丢弃字节、malformed及无候选步仍使用Framer事实，不伪造Decode观察事件。
- 成功时字段身份、类型、值和实际范围由本次执行及其Plan取得；不得再调用Decode自证或补展示。
  需要保存的原帧、字段字节和描述在借用期内复制，不能保留指向工作区的视图。
- 观察在Core返回后进行；观察正常返回STOP只停止后续候选，不取消当前成功候选的业务交付。
  当前失败候选不进入业务Sink；当前成功候选最多进入业务Sink一次。
  观察与业务Sink任一正常STOP均停止后续候选。
- 观察抛异常或Lab复制失败必须停止后续处理，保留实际消费并进入需要Reset/重建的故障态。
  观察异常不再交付当前业务结果；已发生的宿主副作用不承诺回滚，不自动重放。
  Core成功数、业务成功回调数及观察物化成功数不可混为一个计数。
- 未提供观察接口时，原成功业务Sink、失败候选继续与消费语义保持不变。
  同实例重入仍拒绝，观察不赋予并发调用或回调内销毁权限。

Lab使用候选级STOP保证每次按钮最多一个候选；不得用“首个成功结果STOP”替代。
失败原帧明确标为诊断材料，零字段成功仍显示成功事实。

## 3. 绑定、资源与Plan所有权

绑定描述由Lab保存为有界草稿，协议格式仍来自Frozen Plan和Sidecar。草稿修改不改变活动Session，
未应用的草稿不能被当成当前执行绑定。界面须明确区分未应用与已生效状态。

首片沿用宿主层绑定数、身份长度、总通道数与计费硬上限，可收紧不可放大；UI编辑容量亦须有界。
每个Decode绑定预建两条逻辑流（索引0/1），Encode绑定一个通道；总通道上限继续独立校验。
单向Pipeline只允许其支持的动作，Encode Message必须属于已选绑定的Pipeline且支持Encode。
不把TX Message选择器用于指定Decode匹配。

一个Tab的活动Session唯一拥有一份Plan；adapter不得同时保留第二个拥有者。
UI描述/Sidecar如含借用关系，必须在移交前转成自有描述或明确保证生命周期。
活动工作区先于Plan销毁，Tab之间不共享可变工作区，跨Tab句柄拒绝。

应用新绑定需要准备独立候选Session时，通过正常编译/加载路径取得独立PlanOwner，
不从活动Session制造第二个PlanOwner。只在新实例准备成功并获得必要丢弃确认后替换活动实例；
绑定应用失败保留原活动实例并显示草稿未生效。新旧实例同时准备的峰值资源必须计入Lab预算，
不能只引用单Session的AccountedBytes冒充整体内存上限。

Reload仍遵循旧契约：确认终止旧加载后，新配置加载失败不恢复旧半包。
该行为须与“应用绑定失败保留活动实例”在界面和测试中区分。

## 4. 状态隔离、续提与失效

执行结果身份至少包含Tab/加载修订、Session修订、绑定身份、逻辑流索引、流generation和操作序号。
旧Session、旧绑定或旧代结果不得覆盖当前显示。切换流不Reset，不自动提交输入。

每条逻辑接收流独立保存未提交草稿、冻结chunk及消费游标、候选/Decode计数和当前结果。
仍只保存每流当前结果，不增加历史队列；两条流的结果副本纳入有界预算。
Encode草稿及当前结果与接收流隔离，执行Encode不销毁接收半包。

- Submit先整次校验文本和解析后字节容量，再冻结并最多调用一次Push。
- Continue只提交准确未消费后缀；仅有内部pending时才空Push，不刷新半包或丢弃等待状态。
- C继续为min(65536, 有效max_submit_bytes)，不拿单帧M限制整个chunk。
- 每步清理旧展示；非法草稿不调用引擎、不破坏半包，失败与无候选均不得残留旧成功高亮。
- Reset只清所选逻辑流的引擎状态、冻结输入、当前结果及累计计数，并开启新generation。
  未提交草稿与冻结输入区分处理，不得因此重放已消费数据。
- 切换绑定查看或切换Tab保留活动流；应用绑定、Reload、离开流模式和关闭文档涉及丢弃时，
  检查该操作将销毁的全部流，包括未选流的半包、pending、丢弃模式和冻结后缀。
  一次列明受影响范围并确认，取消不改变Session、游标、选择或草稿状态。
- 无进展保护、计数溢出、复制故障及API故障按旧流观察边界处理，不隐藏消费或自动重试。

保留双Tab上限、ASCII escaped/Hex语法和零基UTF-16输入定位；显示表示不等于协议编码模式。
字段范围以当前候选帧内字节偏移呈现，不声称全流偏移。

## 6. 验证矩阵与交付停点

Windows Debug/Release至少覆盖以下针对性检查，具体测试数以实际执行报告为准：

1. PAE观察未启用的旧行为；成功/失败候选观察恰一次，Core恰一次；正常STOP仍交付当前成功结果，
   坏候选后好候选须下一次Continue，零字段成功，早拒绝无伪候选，观察异常保留消费并要求Reset。
2. 有效/空/重复绑定、未知Pipeline、单向动作、跨Pipeline Message、过期句柄、容量拒绝和创建失败；
   草稿未应用不改变活动绑定，应用失败不污染原Session。
3. ASCII 0.10/0.11 Encode与完整记录Decode、0.11 CRLF流；独立RX/TX输入和手算期望，
   不用自身输出回环作为唯一证据。
4. 双流交错半包、粘包、CR/LF分片、精确后缀、内部pending、预算耗尽与超长恢复；
   Reset一流不影响另一流及Encode，跨Tab不串状态。
5. 当前候选原帧/字段范围/失败诊断、复制后独立存活、复制失败、旧结果失效、非法草稿保留状态，
   重建/Reload/关闭对未选流的确认与取消，以及Reload失败不复活旧流。
6. 默认OFF、缺依赖门禁、新启用组合、共享宏及工具链一致；旧ASCII/Binary与普通CLI/Evidence受影响回归。
