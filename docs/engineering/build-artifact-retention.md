# 中间构建产物保留规则

## 默认规则

中间构建产物只保留最近两个已完成的完整批次：当前可用批次和上一可回退批次。一个批次可以包含 SDK、Lab、文档打包和包外验证多个构建根；不能按目录修改时间只留下两个文件夹，也不按每个历史切片各保留两份。

- 新批次验证完成后，先归集旧批次必要的配置、构建、测试日志、来源清单和哈希，再清理第三批及更早构建。
- 正在使用的开发目录、尚未闭合问题的必要复现目录可以临时例外保留，必须注明原因；不能成为无限期保留的默认借口。
- 成品在 `deliverables/sdk`、`deliverables/lab` 单独管理，不属于中间构建；不得借构建清理删除用户正在试用的成品。
- 最小证据留在 Git 忽略的 `deliverables/evidence`，公开报告仅使用仓库相对路径。证据不是完整构建树备份。
- 删除前核对精确路径、重解析点、运行进程、共享任务状态及保护文件哈希。禁止对整个 `out` 或工作区执行递归删除。
- 本规则不创建定时自动清理任务，不授权未来任意删除；后续执行须遵守当轮授权和精确清单。
