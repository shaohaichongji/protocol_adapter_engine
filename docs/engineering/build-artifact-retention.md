# 中间构建产物保留规则

## 默认规则

2026-10-10 用户调整：只保留最新仍有使用价值的构建、交付输入与必要验证记录。不再默认保留上一批回退构建，不为已被替代的历史构建树或日志做备份。

- 新批次验证完成后，按精确清单清理已被替代且无当前用途的历史产物，无需先备份历史日志。
- 正在使用的开发目录、尚未闭合问题的必要复现目录可以临时例外保留，必须注明原因；不能成为无限期保留的默认借口。
- 成品在 `deliverables/sdk`、`deliverables/lab` 单独管理，不属于中间构建；不得借构建清理删除用户正在试用的成品。
- 当前必要证据按实际用途保留，公开报告仅使用仓库相对路径。历史报告记录当时事实，其中旧构建路径可能已清理，不表示原始日志仍可读取。
- 删除前核对精确路径、重解析点、运行进程、共享任务状态及保护文件哈希。禁止对整个 `out` 或工作区执行递归删除。
- 本规则不创建定时自动清理任务，不授权未来任意删除；后续执行须遵守当轮授权和精确清单。
