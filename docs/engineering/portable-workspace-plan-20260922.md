## 拟采用原则（待盘点细化）

1. 公共源码、构建入口和说明使用相对路径、基于脚本目录的路径或显式参数；不依赖作者磁盘布局。
2. 正式产品依赖应随仓固定版本提供；Qt、yyjson 已有随仓副本，先审计闭包而非重复复制。
3. 系统 SDK、MSVC、操作系统不作为项目依赖整套复制；通过发现机制和明确的环境要求接入。
4. 构建缓存不可当可移植成品迁移；可重建的 build、临时输入与真正 SDK/Lab 成品分离。
5. 公共历史报告可用语义别名/相对定位脱敏；原始日志、provenance 和 Hash 不篡改，留在 Git 外的本地证据区。
6. 不对第三方二进制/调试符号进行字符串替换。发现其中的绝对路径时单列处置，不冒充已消除。
7. 归集不等于重新构建，不更改旧产物提交身份；发布材料、私人内容和第三方许可不明确时停止入库。
8. Git 跟踪当前文件的整治与历史提交脱敏是不同操作；重写已推送历史不在本轮范围。
