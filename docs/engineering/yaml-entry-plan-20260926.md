## 目标链路与首版边界

YAML 原文 → 受限、非 Qt 转换前端 → 严格 JSON → CompileProtocolJson → 既有冻结 Plan。

- 面向 YAML 1.2 的明确子集：单文档、根对象、字符串键、对象/数组/基本标量、注释。
- 禁止自定义标签、锚点/别名、合并扩展、多文档、include、环境变量替换和外部资源读取。
- 固定类型解析规则；字符串不得按目标字段偷偷强制转换。版本号、字节文本等应明确作为字符串。
- 保留数字词法与精确范围；不经过 double 中转，不把 2.0、-0 或其他现有 JSON 契约拒绝的形式静默规范化后放行。
- 在键被覆盖前检查重复键，按解码后的键值判断；普通字符串键与合并扩展的区分须在契约中明确。
- 转换前后分别约束输入/输出大小、深度、节点与标量；解析阶段资源控制不能只靠转换完成后的检查冒充。
- 保留 JSON Pointer 与原始编译诊断；另建 YAML 来源行列映射，不把生成 JSON 的偏移冒充 YAML 偏移。
- 首版不修改 CompileDiagnostic 或其他公共 ABI。具体可选前端 API 和打包方式留待探针复核。
- YAML 作为作者源时，JSON 为生成物，不能要求手工双份维护；原有 JSON-only 路径不强制新增依赖。

## 探针最低证据

1. 正例：嵌套对象/数组、中文与注释、字符串转义、精确大整数及行列位置。
2. 负例：解码后重复键、标签/别名/合并、多文档、超深/超大输入；拒绝行为不得靠吞异常伪装成功。
3. 类型边界：带引号版本号、十六进制字节字符串、null/bool、2 与 2.0、-0、前导零及 UINT64/INT64 边界。
4. 一个 Binary 和一个 ASCII 配置的最小等价转换核对；准确区分文本结构等价和实际 PAE 编译/执行等价。
5. 解析器能否在解析阶段限制资源、保留原始标量和定位；无法证明的项目列为缺口，不声明安全闭合。
6. Windows x64 Debug/Release 独立探针构建运行，断言不依赖 Release 下可能被移除的 assert。
