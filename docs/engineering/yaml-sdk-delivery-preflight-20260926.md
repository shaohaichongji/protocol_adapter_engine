# YAML SDK 交付边界预检任务

## 目标与授权

用户同意推进初版交付，YAML 人工体验延期至成品统一体验。本片是接口和交付边界预检，
不实现新接口，不提交或生成替换现用成品。现场基线需重查；派发时为 `main@4da54b9`，
Lab 入口及总控文档存在共享未提交变更，必须保留。

## 执行范围

《子任务推进》只读源码、构建、打包与现有证据，唯一写入文件为
`docs/engineering/yaml-sdk-delivery-design-20260926.md`。无需新构建或重复已有测试。
不得改根 CMake、src、include、Lab、SDK 脚本、第三方、交付目录或其他文档。

报告需给出证据路径、明确推荐及最小实施文件清单：

1. 可选非 Qt YAML 组件与 PAE Core 的单向关系；保持 strict JSON 为编译入口，
   不改变 Schema、执行规则、受限 YAML Profile 或容量默认值。
2. 建议的头文件、命名空间和 CMake target；源包、静态包、动态包各自如何使用，
   默认 OFF 和 JSON-only 安装/链接行为。比较独立静态附加组件与随库类型生成两种方案，
   推荐最小且可验证的方案，不把动态 PAE 加静态前端误称为动态 YAML 组件。
3. 对照现有 `frontend.h` 的 Result 所有权、view 生命周期、失败状态、来源映射、
   预算及分配故障注入参数，明确哪些应保留内部。动态边界必须考虑导出符号、
   创建/释放所在模块、CRT 与既有 SDK 工具链限制，不承诺稳定跨编译器 ABI。
4. 安装规则、PAEConfig、源码包白名单、许可通知、配置/示例的闭包与可搬迁性；
   包外 consumer 不得 include 仓库 src 或引用原仓库/旧 out，依赖不得运行时下载。
5. Lab 由内部接口迁移到上述消费接口的必要改动清单，仅列计划，不改 Lab。
6. 最小验证矩阵：Windows x64 Debug/Release、源码/静态/动态包、JSON-only，
   YAML→JSON→公开编译→Codec 对照、来源诊断及包搬迁；把必要组合与后置项区分，
   不以 Configure 成功代替消费运行，也不增加繁琐人工矩阵。
