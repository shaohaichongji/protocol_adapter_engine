   不新增 Schema，不为 UI 便利改变 PAE 配置语义。

## 3. B组：PAE流式宿主接入

3. 完善既有示例，不另建 Runtime：宿主 Chunk → Framer → 完整帧回调 → Core Decode →
   业务字段。两条独立逻辑流共享不可变 Plan，各自持有 Workspace；宿主主动调用，不引入
   线程、轮询或通讯库。两流测试不构成多线程并发安全证据。
4. 验收覆盖分片、多帧、噪声、无效长度恢复；未消费后缀由宿主准确保留并再次提交；
   STOP和预算耗尽后的继续处理不能形成零进展忙循环。一条流暂停或 Reset不污染另一条流。
   完整帧 Decode失败不触发 Framer重切分；明确回调借用数据有效期，跨回调保存由业务复制。
   宿主 Reset丢弃未完成帧，模拟断链清理。优先只改示例和测试，产品缺陷或接口变更先报告。

## 4. C组：Lab有界变长完整记录UI

5. 在保留 0.5～0.7行为的基础上开放 Schema 0.8 Encode/Inspect。编辑有界 BYTES，
   配置允许时接受空载荷，显示限制，区分非法输入文本和协议长度越界。computed长度与
   校验只读；复用 PAE算法，不在 Qt重写长度或校验。0.9继续拒绝，不接 TCP/UDP/串口。
6. 成功结果决定实际帧长度、载荷范围、动态尾部和校验位置。无有效结果时不得把最大长度
   布局当作当前布局；失败只展示可靠定位，不交付伪成功字段。输入变更、重新加载及模式
   切换遵守既有失效规则，清理旧结果和高亮。
7. 实施前集中给出执行桥、字段描述和位置映射的接入差异清单。已有接口足够时，可在后续
   整体实施授权内继续；必须扩展共享接口时，先由总控核定最小范围及回归集合。
   不重构整个 Lab，不增加 Evidence版本，不扩大 CLI接受域。
8. 每侧按一个完整检查点收口。PAE运行宿主示例及受影响 Framer/Core的 Windows

   旧代必要回归。人工仅保留一次简短动态布局可用性检查。合并时一次集成验证，不无理由
   重跑全部历史矩阵。实施与 Git交付授权分开；默认不 Stage、Commit、Merge、Push。
