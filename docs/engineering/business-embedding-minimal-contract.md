# 最小业务嵌入验证：已确认契约

确认日期：2026-09-08。状态：八项已确认；已授权并完成限定实施与Windows离线验证，待总控审查。
代码基线：`df43165`。本契约不发布稳定公共API（应用程序编程接口），不改变既有Core契约。

## 1. 目标与交付形态

新增`examples/business_embedding`独立宿主示例、对应自动化测试及简短接入说明。
以C++17直接链接Compiler、Plan和Core，不启动Lab子进程，不引入Qt、Socket、线程或新依赖。
验证源码集成和业务调用，不证明设备通信成功；不安装、导出或承诺稳定公共接口。

## 2. 一条连接、两个方向

使用一份公开合成主配置，定义RX（接收）测量/状态报文和TX（发送）动态设定值报文；另提供一份
保持业务语义和类型、但改变偏移或比例的适配变体。
两方向采用不同消息标识及布局、独立Pipeline（处理管线）。只使用已实现的整数、状态位、
Decimal64（十进制定点值）和SUM8（逐字节求和取低8位），不扩展字段类型。

## 3. 示例层接口

概念接口为`Initialize(config_text, callbacks)`、`OnReceivedRecord(bytes)`和
`SendCommand(command)`；名称及具体返回类型按现有仓库风格落实，不构成公共API冻结。
回调为`OnMeasurement(measurement)`和`OnBytesReady(bytes)`。

初始化时按字符串ID解析并校验消息、字段和类型，缓存既有FieldRef（字段引用）。运行时使用
缓存引用和类型化值，不逐帧解释配置。初始化失败不得进入收发调用。
接收入口只接受一条完整报文，不负责拆包、粘包或持续监听；调用返回值携带明确错误，
不新增错误总线。这是示例薄封装，不建设通用注册框架。

## 4. 类型化业务对象

示例Measurement包含Decimal64测量值及BOOL告警；Command包含Decimal64目标值。
业务层不处理偏移、大小端、raw整数或Checksum（校验和），不将所有值字符串化。
字符串用于初始化绑定，通用键值访问接口后置。
配置适配以业务字段语义和类型不变为前提；含义或类型改变仍可能要求宿主修改。

## 5. 执行及生命周期

调用方驱动、同步调用和同步回调，没有后台轮询。RX/TX各自持有独立Workspace（执行工作区），
共享不可变Plan。宿主串行调用同一示例实例，本轮不承诺并发或回调重入。
Plan必须比字段引用和Workspace活得更久。
回调数据只保证在该回调期间有效；需要异步保存或发送时，宿主必须复制到自己的存储。
验证复制后数据不被后续调用影响，不将该示例宣称为通用并发Session（会话）。

## 6. 失败门禁

Decode成功才调用一次业务回调；Encode成功才调用一次待发送字节回调。
任何失败返回明确错误，不触发该方向成功回调；失败后的编码缓冲区中间内容不得交付。
字节交付不表示通信发送成功，更不表示设备执行成功。
不实现重试、排队、优先级、一对多路由或通用Receive Gate（接收门禁）框架。

## 7. 验收范围

| 组 | 必须断言 |
| --- | --- |
| 初始化 | 合法绑定成功；缺失字段或类型不符在收发前拒绝 |
| 正常RX | 固定输入字节得到精确业务值，业务回调恰好一次 |
| 动态TX | 至少两组运行时业务值生成独立预期字节，发送回调各一次 |
| 方向隔离 | TX报文误投RX不能交付测量结果 |
| 配置适应性 | 第二份配置改变偏移或比例，业务语义不变，同一宿主代码仍能运行 |
| 失败不交付 | SUM8错误、未知报文、非法Decimal、不可精确反算均不触发成功回调 |
| 状态恢复 | 成功、失败、再次成功之间不残留可冒充本次结果的旧状态 |
| 生命周期 | 回调中复制的业务对象和字节不受后续调用影响 |

预期字节和数值不得用被测Encode/Decode生成；往返检查只能作为补充。
复用既有错误类别，不建设新诊断体系。测试使用公开合成资料，不纳入客户协议或现场数据。
