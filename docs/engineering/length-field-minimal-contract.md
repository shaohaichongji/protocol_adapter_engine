## 1. 已确认范围

- 仅固定长度`COMPLETE_RECORD（完整记录）`，每Message至多一个长度字段；允许不声明长度字段。
- Decode（解析）验证长度值，Encode（组包）由引擎自动回填；RX/TX分别按各自Message配置。
- 只支持整帧`frame`或帧内一段固定连续区域`region`，单位为字节。
- 存储为字节对齐的1/2/4字节无符号整数，逻辑类型为`UINT64`；不接受位字段、带符号、BCD或Decimal转换。
- 不支持固定偏置、比例、其他单位、表达式、变长BYTES、数组、TLV、切帧、网络或线程。
- Core不拥有通讯接口；本检查点不扩展Session、路由调度、稳定公共API或Qt UI。
- 计数区域可以包含长度字段自身、Matcher字节或校验存储；校验覆盖区域也可以包含长度字段。
  长度先写、校验后生成；计数字节数不读取校验值，不构成计算依赖环。
- 一次完整实施检查点、一次集中审查；范围内修正及受影响回归集中完成，Git另行授权。

## 2. 第一组：配置和冻结模型

### 1. computed长度原语

沿用现有字段`id`、`value_type`和`wire`结构，新增以下属性组合。下面是字段内的JSON片段，
不是可直接加载的完整配置；实际配置仍需置于完整的Schema 0.7 Message字段结构中。

整帧计数：

```json
"encode": {"source": "computed"},
"computed": {"kind": "length", "scope": "frame"}
```

区域计数：

```json
"encode": {"source": "computed"},
"computed": {
  "kind": "length",
  "scope": "region",
  "range": {"byte_offset": 4, "byte_length": 14}
}
```

- `frame`禁止提供`range`；期望值来自Message的`frame_length_bytes`，不重复配置。
- `region`必须提供`range`，从完整报文起点计算，`byte_length > 0`；区间为
  `[byte_offset, byte_offset + byte_length)`，加法安全且完整落在帧内。例如20字节帧的`[4,18)`计14字节。
- `computed`与`encode.source=computed`必须成对出现；`kind`只接受`length`，`scope`只接受上述两值。
- 不允许常量值属性、`conversion`或其他计算规则；沿用严格JSON的重复、未知、缺失属性拒绝规则。
- 1字节存储禁止填写`byte_order`；2/4字节必须指定`big_endian`或`little_endian`。
- 长度字段有稳定ASCII `id`。Encode业务输入省略该字段，成功Decode按配置字段顺序返回普通`UINT64`。

### 2. 冻结、重新推导和资源计费

固定帧的长度期望在启动编译时确定：`frame`等于帧长，`region`等于区域字节数。
每Message冻结一个可选长度描述，关联字段索引、范围和期望值；不创建通用表达式执行器。
Compiler检查期望值能否由Wire宽度表示，Builder独立重算并检查描述、索引、唯一性、范围及关联，
不能信任Draft中的派生值。合法宽度的上限分别为255、65535和4294967295。

新增实际存储及对齐全部纳入既有Plan计费；不得漏算因承载结构扩展产生的开销。
长度字段不占业务输入槽，不新增长度专用Workspace缓存；运行期不读取配置或新增动态分配。
本阶段是固定帧的长度一致性验证，不是根据字段值决定实际读写范围。

### 3. 存储与匹配隔离

长度存储不得与其他普通字段、位容器、校验存储或`fixed_bytes` Matcher（固定字节匹配条件）重叠。
长度值不能参与结构候选消歧；不得利用长度值截断、补齐报文或决定越界读取。
上述禁止重叠针对长度的存储位置，不针对计数区域；计数区域的允许包含关系见第1节。
每Message仍至多一条既有完整性规则，选择SUM8或CRC，不新增多校验依赖。

## 3. 第二组：执行和错误语义

### 4. 错误分类

| 场景 | 状态/阶段 | 身份与输出 |
| --- | --- | --- |
| 业务显式赋值长度字段，即使值正确 | `COMPUTED_FIELD_OVERRIDE` | 字段身份及输入索引；不交付有效输出长度 |
| Decode内部长度值与冻结期望不同 | `LENGTH_MISMATCH` | 字段身份，无输入索引；零字段交付 |
| 配置期望不能由Wire宽度表示 | 编译失败，定位计算规则 | 不发布Plan |
| 冻结描述损坏 | `INVALID_PLAN` | 沿用既有防御及失败交付约定 |

新增Codec状态追加，不改变既有枚举值。常量赋值仍返回`CONSTANT_FIELD_OVERRIDE`，不得将计算字段
误报为常量。长度错误不属于Decimal转换错误，`conversion_error`保持空。
期望值与实际值可写入诊断说明，本阶段不新增专用机器字段；使用配置、原始Frame与失败身份复现。

### 5. 失败优先级

- Encode：引用/禁止赋值/重复输入检查 → 必填检查 → 业务值检查 → 输出安全与容量 →
  写业务及常量 → 写长度 → 生成SUM8/CRC → 最终复核 → 整体交付。
- Decode：结构唯一性 → 容量与安全 → 长度一致性 → SUM8/CRC → 字段处理 → 整体交付。

继承现有参数、Plan、Workspace入口门禁及各阶段内部顺序，不将这两个顺序表解释为取消既有安全检查。
输入总字节数不符合任何固定结构，仍按既有未知报文判定；仅已确定结构的内部长度值不符才返回
`LENGTH_MISMATCH`。多候选仍返回歧义，不执行长度或校验以选择候选。
长度与CRC同时错误时长度先失败；首个失败是执行顺序结论，不等于现场故障根因。

### 6. 最终复核与整体交付

Encode最终复核重新读取实际输出中的长度字节，与冻结期望比较，并继续执行既有完整复核；
不能只相信预先算出的长度。实际字节或结果不符返回`FINAL_REVIEW_FAILED`，内部故障保留
`INTERNAL_ERROR`。失败不交付有效字段或有效输出长度，诊断生命周期遵守既有契约。
保持调用方缓冲区所有权规则，不新增“失败时擦除整个缓冲区”的承诺。

长度校验属于主Codec内部步骤，不新增专用阶段事件；不增加Values类型、CLI命令或退出码分类，
失败复用已有CLI分类及期望状态机制。本次不机械升级产品版本或所有文件格式。

### 8. Lab复用与兼容边界

接入既有Encode、Inspect、RUN证据、Replay、Compare及父Record/历史Result关联。
新实现保持旧代合法证据可读；旧代Reader不接受新代状态。跨指纹域不直接判定执行结果相等，
原始字节比较保留原规则；失败重放可以与历史比较相等，但不把当前执行失败变为成功。
沿用分层Reader：底层检查证据关联，运行关联层核实冻结Plan中的字段身份及语义。
复用现有模块、事务写入及测试设施，不因代次递增复制完整Reader/Writer，也不拆成A/B/C平行接线。
